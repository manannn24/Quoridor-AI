# Testing and Acceptance Criteria

The project is not complete until these criteria are satisfied or each unavoidable environment limitation is clearly logged.

## 1. Engine unit tests

### Initial state

- 9×9 board semantics, starting pawns at `(8,4)` and `(0,4)`.
- Both players start with 10 walls.
- Human moves first.
- No winner initially.

### Normal pawn movement

- Orthogonal legal moves are generated.
- Out-of-bounds moves are rejected.
- A wall blocks the correct edges.
- A pawn cannot land on the opponent's occupied cell unless the move follows the jump rules.

### Jump rules

- Straight jump when adjacent to the opponent with a clear landing cell.
- Straight jump is prohibited when the rear edge is blocked or beyond board bounds.
- Diagonal jump options exist when the straight jump is blocked by a wall/edge.
- Diagonal targets are rejected when off-board or blocked.
- Diagonal jump is not offered when straight jump is available.

### Wall placement

- Valid horizontal and vertical walls block the expected movement edges.
- Out-of-range anchors are rejected.
- Existing wall overlap is rejected.
- Perpendicular crossing is rejected.
- Legal endpoint adjacency is handled according to the documented geometry.
- Wall placement with no walls remaining is rejected.
- A wall that removes all paths to goal for either player is rejected.
- A valid wall decrements only the active player's wall count and consumes a turn.
- An invalid wall leaves the entire state unchanged.

### Winning and turn control

- Reaching the opponent's goal row ends the game immediately.
- No action is accepted after game end.
- Valid actions switch turns exactly once.

## 2. Pathfinding tests

- BFS and A* return equal shortest path lengths on the initial board.
- They return equal distances after representative horizontal/vertical walls.
- They agree on seeded randomly generated legal states.
- Pathfinding respects all wall-blocked edges.
- Each goal-row cell is a valid goal and gives distance zero for that player's goal test.

## 3. AI tests

- Greedy, Minimax, and Alpha-Beta return legal actions from several valid states.
- An immediately available winning pawn move is chosen over nonwinning alternatives.
- Search detects terminal outcomes at the correct depth.
- At shallow depth, Minimax and Alpha-Beta return the same score and deterministic action with the same candidate-action settings/order.
- Alpha-Beta reports cutoffs on a scenario that enables pruning; if a test fixture cannot guarantee a cutoff, use a deterministic constructed tree/search state that does.
- Minimax has zero Alpha-Beta cutoffs.
- Search leaves the input state unchanged.
- AI vs baseline seeded simulations do not produce illegal actions or corrupted states.

## 4. UI tests

At minimum test:

- Board renders both pawns and wall reserves.
- A legal human pawn move triggers a computer response.
- Invalid wall placement displays a message without changing the turn/state.
- New Game resets positions, walls, status, and metrics.
- AI thinking disables interaction (or otherwise prevents actions from being processed mid-search).
- Winner state is displayed.
- Strategy/depth selectors update the configured next AI search.

## 5. Required commands

Implement package scripts equivalent to:

```bash
npm run dev
npm run build
npm run test
npm run typecheck
npm run lint
npm run benchmark
npm run check:all
```

`npm run check:all` must run the meaningful noninteractive checks (at least lint, typecheck, tests, build). Do not include a long full tournament in `check:all`.

## 6. Manual smoke test

Document this quick checklist in the README:

1. Start the app.
2. Make a normal move; verify AI responds.
3. Place a horizontal wall.
4. Place a vertical wall.
5. Try an invalid/crossing/overlapping wall; verify it is rejected.
6. Reach a jump scenario or use a test scenario if the UI offers a developer-only setup.
7. Complete a game and verify winner state.
8. Start a new game.
9. Switch AI modes and compare displayed metrics.
10. Run `npm run check:all` and `npm run benchmark`.

## 7. Definition of done

- The game is actually playable, not just a visual mockup.
- The engine's rules are covered by automated tests.
- A human can complete a full match against AI.
- Each AI agent returns legal actions.
- Minimax and Alpha-Beta have a fair same-action-tree comparison test.
- Benchmark results are generated by running the benchmark, not invented.
- All essential commands work and are documented.
- No browser console errors or uncaught errors in the normal flow.
- README, AI design, limitations, and implementation status reflect the actual final implementation.
